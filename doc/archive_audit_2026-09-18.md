**Slidescape archive audit — 18 September 2026**

Follow-up: the immediate fixes have now been applied. See [implementation notes](archive_audit_followup_2026-09-18.md). Findings and line references below describe the audited baseline.

The current architecture is worth continuing. Immutable source bytes, retained generation recipes, aggregate virtual DICOM shells, and transactional representation publication are useful boundaries. HTTP routes already avoid vendor-specific tile logic; explicit binary encoding avoids compiler-layout dependencies; digest checks and no-overwrite object installation are good foundations. A rewrite would discard useful work.

The implementation is still a development archive. The most valuable next work is to correct published metadata and ingest semantics, remove avoidable frame-path work, and introduce a storage boundary that can serve local files, S3 objects, and ZIP members. Native TIFF should then use that boundary.

Scope: reviewed the archive modules, their tests and architecture documents, and relevant TIFF, decoder, platform, and CMake paths. This is a source audit with targeted experiments, not a complete DICOM conformance assessment or a production load test. Findings marked **reproduced** were exercised against disposable synthetic inputs. Other findings identify specific source behavior; predicted scaling and deployment effects are distinguished below.

**Verification**

- Built `slidescape_archive` and `slidescape_tests` with the existing macOS arm64 Debug configuration.
- CTest passed: 109 doctest cases, 428,209 assertions, two explicitly skipped cases. Fixture availability still determines some coverage; this does not establish a fixture-independent public test baseline.
- Ran a disposable Part 10 ingest/re-ingest/failure probe and a localhost HTTP probe. No existing archive repository was modified.
- Ran a small native-payload lookup benchmark against the built archive library. Timings below are debug-build measurements, not production throughput estimates.
- Windows, Linux, sanitizers, remote object storage, and sustained concurrent load were not executed. Implementation source was left unchanged; this report is the only added source-tree document.

**Findings, ordered by urgency**

1. **P1 — WADO metadata changes image provenance and omits necessary pixel and frame semantics. Reproduced in part.** The synthetic source had `ImageType=DERIVED\PRIMARY\VOLUME\RESAMPLED`; WADO returned `ORIGINAL/PRIMARY/VOLUME`. The same response omitted Planar Configuration, High Bit, and Pixel Representation even though the input contained them. The shell retains several of these values but its attribute writer does not emit them. The per-frame serializer emits only matrix row and column, discarding retained optical-path assignment and physical X/Y/Z information. Origin, orientation, and concatenation information also need a complete projection contract. Multi-path or multi-plane frames can consequently lose their distinguishing coordinates in the response. Fix the typed shell fields and projection together, or reject unsupported profiles before publication. Add semantic input/shell/JSON comparisons, including derived pyramids, sparse multi-path data, and concatenations. References: [attribute construction](/Users/pieter/code/slidescape/src/archive/archive_shell.c:224), [ImageType projection](/Users/pieter/code/slidescape/src/archive/archive_instance_provider.c:495), [per-frame projection](/Users/pieter/code/slidescape/src/archive/archive_instance_provider.c:709). The [DICOM WSI module](https://dicom.nema.org/medical/dicom/current/output/chtml/part03/sect_C.8.12.4.html) defines the four ImageType values and required pixel attributes; [optical-path identification](https://dicom.nema.org/medical/dicom/current/output/chtml/part03/sect_C.8.12.6.2.html) connects frames to optical paths.

2. **P1 — Adding an unrelated slide to an ingest batch conflicts with an unchanged published slide. Reproduced.** Ingesting `a.dcm` succeeds. Ingesting a directory containing unchanged `a.dcm` plus an independent `b.dcm` fails with `shell representation conflicts with existing publication`; B is not published. One descriptor covers the entire invocation, and its digest enters every series recipe. Adding B therefore changes A's fingerprint, while publication hardcodes representation version 1. This also affects the documented workflow of adding files below `objects/` and running ingest again. Give each logical slide a canonical membership digest independent of the scan batch. Define replay, incomplete-series completion, and explicit replacement/versioning separately. References: [descriptor construction](/Users/pieter/code/slidescape/src/archive/archive_ingest.c:258), [recipe input](/Users/pieter/code/slidescape/src/archive/archive_ingest.c:653), [fixed publication version](/Users/pieter/code/slidescape/src/archive/archive_database.c:1432).

3. **P1 before accepting untrusted sources — Decoder resource limits are applied after decoding.** The generated RGB path invokes JPEG/OpenJPEG before checking output dimensions and the 64 MiB output limit. Compressed input size does not bound decoded memory. The shared JPEG helper also allocates its output without checking allocation failure and does not free that buffer on a later decoder longjmp. An admitted malformed or unexpectedly large codestream can exhaust memory or crash a worker process; the frame-response limit does not prevent this. Inspect headers first, enforce expected dimensions and a decoded-memory budget, and make decoder cleanup allocation-safe. For eventual remote admission, isolate parsing/decoding jobs from the serving process. References: [archive decoding](/Users/pieter/code/slidescape/src/archive/archive_instance_provider.c:2077), [JPEG allocation/error handling](/Users/pieter/code/slidescape/src/utils/jpeg_decoder.c:135), [OpenJPEG decode order](/Users/pieter/code/slidescape/src/utils/jpeg2000_decoder.c:89). This is a code-path finding; no destructive exhaustion test was run.

4. **P2 — Native MRXS frame lookup is O(total frames), including on a warm cache. Measured.** `archive_shell_get_native_payload()` calls a validator that scans every size record on every requested frame. This duplicates validation already performed when opening the immutable shell. For 100 lookups, the debug probe measured 5.1 ms at 10,000 frames, 32.8 ms at 100,000, and 253.6 ms at 1,000,000. Validate the complete map once, retain a validated view, then bounds-check and read just the requested entry. Preserve validation in public parsing boundaries. References: [linear validation](/Users/pieter/code/slidescape/src/archive/archive_shell.c:2283), [per-frame call](/Users/pieter/code/slidescape/src/archive/archive_shell.c:2681).

5. **P2 — Frame service depends on building full metadata, and cache limits do not bound memory.** Every instance cache miss serializes metadata and, for Part 10, expands all payload ranges before serving a frame. Sparse metadata reserves 192 bytes per frame, capped at 256 MiB; beyond approximately 1.4 million frames, even an otherwise small frame request cannot acquire the instance. Sixteen instance entries can retain several GiB of metadata, plus payload arrays and shells. Concurrent misses for the same instance duplicate this preparation before one entry wins insertion. Split shell/range access from lazy metadata generation, use byte and file-descriptor budgets, and coalesce in-flight loads by key. Fixed-stride maps need no expanded array; delta maps could use checkpoints or a bounded decoded cache. References: [capacity calculation](/Users/pieter/code/slidescape/src/archive/archive_instance_provider.c:830), [cache preparation](/Users/pieter/code/slidescape/src/archive/archive_instance_provider.c:1648), [cache admission](/Users/pieter/code/slidescape/src/archive/archive_instance_provider.c:1682).

6. **P2 — Multipart responses retain all frames and then copy them into a second full response buffer.** A response near the 256 MiB cap retains roughly 512 MiB of payload buffers until sending completes, before caches and decoder working memory. Worker concurrency multiplies this. Send validated frame buffers and multipart headers directly, retaining the same ordering and early-error behavior initially. Later add streaming/batched reads and a global in-flight byte budget. The simplest first improvement removes the second full copy. Reference: [response assembly](/Users/pieter/code/slidescape/src/archive/archive_http.c:348).

7. **P2 — Failed ingestion leaves bundles marked PUBLISHED. Reproduced.** A source with a short native Pixel Data element passes initial metadata registration, then fails shell generation. Its bundle nevertheless remains `PUBLISHED`; the batch-conflict experiment also left a second such bundle. Representations remain correctly hidden, so this is not evidence of partial WADO visibility. It is a misleading durable state that complicates retry, cleanup, accounting, and future jobs. Register bundles as STORED or STAGED and perform the final bundle/representation/publication transition together. References: [Part 10 registration](/Users/pieter/code/slidescape/src/archive/archive_database.c:929), [MRXS registration](/Users/pieter/code/slidescape/src/archive/archive_database.c:1171), [ingest ordering](/Users/pieter/code/slidescape/src/archive/archive_ingest.c:551).

8. **P2 / architectural prerequisite — Object identity and placement remain coupled.** The object table permits exactly one of a filesystem key, external path, or inline bytes; registering identical bytes with another location conflicts. This prevents straightforward reference-to-owned promotion, replication, or local-to-S3 migration. MRXS additionally embeds an absolute path in its retained recipe and resolves companion payloads directly from that directory. Changing location changes recipe bytes without changing its representation fingerprint, producing a provenance conflict on replay. Introduce separate logical members, content identities, and mutable/versioned placements. Make recipes refer to member identities, never machine paths. References: [object schema](/Users/pieter/code/slidescape/src/archive/archive_database.c:39), [placement conflict](/Users/pieter/code/slidescape/src/archive/archive_database.c:495), [MRXS recipe](/Users/pieter/code/slidescape/src/archive/archive_mrxs_adapter.c:186), [MRXS source opening](/Users/pieter/code/slidescape/src/archive/archive_instance_provider.c:1250). Existing reference mode is explicitly developmental; this is a migration blocker, not a claim that it promises owned retention today.

9. **P2 — The startup index has both scaling and publication-consistency limitations.** Duplicate checks linearly scan prior records, giving quadratic loading work; frame lookup scans the full instance array. The current instance record is 5,664 bytes on this build, so one million records alone consume about 5.3 GiB. The three index SELECTs lack an encompassing read transaction, allowing an ingest commit between them to produce an inconsistent startup projection. Serving then holds that projection indefinitely, requiring restart to see new publications. Use one read snapshot immediately. For scale, query indexed SQLite tables or maintain compact UID lookup structures, and introduce an explicit publication-generation refresh mechanism. PostgreSQL is not required to fix these issues. References: [append checks](/Users/pieter/code/slidescape/src/archive/archive_index.c:144), [startup loading](/Users/pieter/code/slidescape/src/archive/archive_index.c:243), [linear lookup](/Users/pieter/code/slidescape/src/archive/archive_index.c:406).

10. **P2 — Frame capabilities have multiple competing authorities.** The database's syntax mapper accepts JPEG variants the runtime mapper does not advertise. Generated RGB availability is computed separately at runtime. The index joins every STORED/GENERATED representation row into its instance query; adding a second persisted alternative would duplicate the SOP row and fail duplicate validation. Keep an instance's source syntax separate from its list of available frame representations. Share a small capability table or provider contract among validation, publication, negotiation, and retrieval. References: [database mapper](/Users/pieter/code/slidescape/src/archive/archive_database.c:1271), [runtime mapper](/Users/pieter/code/slidescape/src/archive/archive_instance_provider.c:1860), [index join](/Users/pieter/code/slidescape/src/archive/archive_index.c:305).

11. **P2 before broader native support — MRXS publishes assumptions that need admission checks.** The adapter fixes YBR_FULL_422 and SRGB while the serving path only checks JPEG SOI bytes. It does not establish JPEG coding process, dimensions, sampling/color agreement, or preserved scanner ICC semantics. Only known referenced files are included in its descriptor, and the original companion directory is replaced by the logical `companion/` prefix. Native serving and original-package preservation therefore need separate completeness criteria. Keep the narrow profile, validate each admitted codestream sufficiently for its promised syntax, and represent inferred versus preserved metadata explicitly. Also decouple native Study/Series identity from adapter-version-derived fingerprints: the current UID generation changes all identities when that fingerprint changes. References: [native metadata](/Users/pieter/code/slidescape/src/archive/archive_mrxs_adapter.c:248), [JPEG check](/Users/pieter/code/slidescape/src/archive/archive_instance_provider.c:2004), [bundle membership](/Users/pieter/code/slidescape/src/archive/archive_ingest.c:340), [UID derivation](/Users/pieter/code/slidescape/src/archive/archive_mrxs_adapter.c:30).

12. **P2 for VPS operation — HTTP and repair remain development infrastructure.** Socket timeouts apply to individual operations rather than total request deadlines, so a slow client can occupy a worker indefinitely by making periodic progress. A 1,024-task queue can retain many sockets; worker count and memory are not an archive deployment policy. Detailed provider errors are discarded into generic 409 responses. A missing Part 10 shell can trigger full-source hashing/parsing inside a request under a process-wide repair lock; MRXS has no equivalent automatic repair. Add bounded admission, deadlines, cancellation, useful structured errors/logging, and repair jobs. Keep the current loopback binding behind an authenticated gateway for an initial trial. References: [socket timeout](/Users/pieter/code/slidescape/src/archive/archive_http.c:187), [dispatch](/Users/pieter/code/slidescape/src/archive/archive_http.c:578), [regeneration](/Users/pieter/code/slidescape/src/archive/archive_instance_provider.c:917).

13. **P3 — Small inconsistencies expose duplicated policy. Reproduced in part.** `/health` reports repository schema 1 while the repository uses 2. Part 10 publication records adapter version `7`, while its recipe says `9`; MRXS bundle registration says `2`, while the adapter and recipe say `5`. Some version domains may intentionally differ, but names and contracts currently do not explain that. `Accept: image/jpeg;q=NaN` is accepted because floating-point range checks do not reject NaN. Use named version domains, a single current-profile definition, and strict qvalue parsing. References: [health](/Users/pieter/code/slidescape/src/archive/archive_http.c:477), [publication defaults](/Users/pieter/code/slidescape/src/archive/archive_database.c:1297), [recipe version](/Users/pieter/code/slidescape/src/archive/archive_shell_recipe.c:119), [quality parsing](/Users/pieter/code/slidescape/src/archive/archive_representation.c:133).

**Code clarity and deletion/replacement candidates**

- Split responsibilities where they are already distinct. `archive_instance_provider.c` mixes cache lifetime, source resolution, recipe parsing, regeneration, DICOM JSON, codec selection, and frame I/O. Extract metadata serialization, recipe codecs, and source reading first. `archive_shell.c` can separate encoding/building from validated views and payload-map access without changing its format. Avoid introducing a class hierarchy or general plugin framework.
- Replace the native adapter's fabricated `dicom_instance_t` input with a small format-neutral instance description. `archive_database_part10_member_t` is already used for MRXS publication, and `archive_shell_build_part10*` builds native shells. Those names now conceal their responsibilities. Preserve an explicit Part 10 parsing adapter feeding the common description.
- Use enums for finite concepts: source roles, provider kinds, frame source/transform kinds, publication states, and serialized field slots. Use named constants for wire offsets, DICOM UIDs/tags, descriptor ordinals, and version identifiers. Cache byte budgets, timeouts, and queue depth are configuration values, not enums. Existing frame-map/section enums are good precedent. Do not replace explicit portable binary encoding with packed C structs.
- Particularly worthwhile constants are the `record + 184`/`record + 188` shell fields, `string_offsets[15]`, MRXS `object_index - 3`, repeated transfer-syntax strings, and defaults repeated in both validation and insertion. A field-offset enum and one profile definition would improve reviewability considerably.
- Consolidate the three archive file-hashing loops, duplicate bounded JSON string writers, and digest/UID validators. Reuse the existing strict DICOM UID validator. Prepare SQL statements once per transaction where practical; retain explicit bindings and cleanup rather than building an ORM.
- `archive_mrxs_adapter_get_rgb_frame()` and `_get_jpeg_frame()` are used by fixture tests, not the current production frame provider. They use dense grid frame numbering while published MRXS frames enumerate only occupied tiles. Move them to test helpers or replace them with an explicitly named tile-index oracle; retaining two public APIs called “frame” invites incorrect future reuse.
- The single-instance recipe/repair branch is not used by current ingest but still has tests and a repair caller. Decide its compatibility obligation explicitly before deleting it. The `archive_database_publish_part10_shells()` forwarding wrapper adds little value after publication types become neutral.
- Do not reuse the old `tiff_serialize`/`tiff_deserialize` remote-viewer protocol for native archive TIFF. Its round-trip test is explicitly skipped, and `tiff_deserialize()` writes a terminator one byte past its JPEG-table allocation at [tiff.c:1343](/Users/pieter/code/slidescape/src/tiff/tiff.c:1343). This path is outside current archive serving, but is a concrete reason to keep the new adapter on the shell contract. The archive's stub `download_remote_chunk()` also shows an old remote-TIFF dependency leaking through the nongui library; separate it as a focused dependency cleanup.
- Replace stale design-document passages about staged manifests/future publication. Document current loopback IPv4/IPv6 behavior, MRXS reference-only ownership, actual shell/recipe versions, migration policy, and which supported profiles have tests. The current `check` command validates layout/schema, not object digests or retrievability; name or document it accordingly and add an explicit deep verification mode.

**Proposed shared storage design**

Use three levels: a bundle member preserves relative path, role, byte size, and SHA-256; a placement maps those logical bytes to a whole blob or a contiguous region of a blob; a backend resolves that blob to a local file or immutable S3 object/version. Source adapters request bounded reads from logical members. HTTP sees instances and frame representations only.

A small C interface for object metadata, opening a source, `read_at(offset, size)`, closing, and immutable upload is sufficient. Backend failures should distinguish missing data, integrity failure, unsupported representation, transient unavailability, and exhausted resources. A frame may need a short list of source spans plus a transform, for example TIFF JPEG tables followed by tile bytes. Keep 64-bit sizes/offsets and checked addition throughout.

Initially keep SQLite and shells on the VPS's persistent local disk, and put bulk sources in S3-compatible storage. Introduce another database only when multi-writer/replica requirements justify it. Publish a representation only after required blobs have been uploaded and verified; a failed database commit can leave an unreferenced immutable blob for later garbage collection. Reclaim staging, aborted multipart uploads, and unreferenced blobs through explicit recoverable jobs.

For S3, implement endpoint/region and addressing configuration, credential refresh, bounded retries, connection reuse, range verification, cancellation, and upload recovery behind this interface. Preserve independent SHA-256 identities: multipart ETags are not reliable whole-object MD5 or SHA-256 identities. AWS S3 accepts only one byte range per GET, so sorted/coalesced reads and bounded parallel GETs matter for a multi-frame response; restore the client's requested frame order afterward. Test the chosen compatible server's behavior explicitly. See [GetObject](https://docs.aws.amazon.com/AmazonS3/latest/API/API_GetObject.html) and [S3 integrity documentation](https://docs.aws.amazon.com/AmazonS3/latest/userguide/checking-object-integrity-upload.html).

**ZIP64 store-only is a good fit, with an explicit preservation contract**

Use ZIP method 0 with ZIP64 sizes/offsets, one immutable blob per original source package. Retain all original member bytes and relative names, including files not needed by the viewer. Decide whether empty directories, timestamps, and other filesystem attributes are part of “original form”; byte-identical files and directory structure should be the initial guarantee.

Build and validate a member index during ingest: normalized safe relative path, uncompressed size, SHA-256, CRC32, and payload start offset. For an uncompressed member, a source range maps to `zip_member_payload_offset + source_offset`; serving need not extract the package or parse its central directory for every tile. Check member bounds before translating to blob bounds. Keep the member index locally with shells/control metadata.

Use CRC32 for ZIP compatibility and SHA-256 for archive identity. Treat the logical package digest separately from the ZIP blob digest so changes to packaging order/timestamps do not redefine source content or DICOM identity. Specify deterministic ordering and packaging metadata if reproducible ZIP bytes are useful. Preserve original timestamps in a manifest if the chosen canonical ZIP encoding normalizes them.

Validate local/central headers and ZIP64 extra fields; reject traversal, ambiguous duplicate names, unexpected compression/encryption, and unsupported link types. Test >4 GiB members, >4 GiB offsets, many members, empty files, Unicode names, and complete export/extract/hash round trips. Streaming writers can finalize the directory at the end; aborted output must never become published. Repacking a changed member rewrites the blob and cross-package file deduplication is reduced, which is reasonable for immutable WSI originals. These recommendations follow the layout in the [PKWARE ZIP specification](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT).

The repository already contains a miniz header with ZIP64 APIs, but its build currently includes only `miniz_tinfl.c`; do not mistake that for an available ZIP writer. Evaluate a small vendored ZIP implementation or the required miniz archive sources and test the restricted profile thoroughly.

**Native TIFF scope**

Start with an explicit profile: tiled brightfield pyramidal TIFF/BigTIFF, supported integer RGB layout, known spacing, and validated JPEG-compressed tiles. Read metadata once during ingest using the existing TIFF parser, then generate a neutral shell and payload map from `tile_offsets`/`tile_byte_counts`. Use the actual IFD dimensions and resolution relationships; do not copy MRXS's `1 << level` assumption. Preserve ICC, source photometric interpretation, lossy history, and associated-image identity.

TIFF JPEG tiles are not necessarily standalone JPEG streams: `JPEGTables` may carry required shared tables. Implement a bounded JPEG reconstruction operation that preserves compression, or reject that variant initially; do not silently re-encode. [TIFF Technical Note 2](https://libtiff.gitlab.io/libtiff/specification/technote2.html) describes this dependency. Aperio variants also use distinct JPEG 2000/color conventions, so label support by tested profile rather than filename extension; see [OpenSlide's Aperio format description](https://openslide.org/formats/aperio/).

Keep every original byte even when label/macro/strip-based associated images are not yet exposed as DICOM instances. Follow the first profile with associated images, validated JPEG 2000, additional vendor metadata, and broader color/bit-depth/planar layouts. Harden the reused parser's size arithmetic, IFD-cycle handling, allocation failures, and error paths before accepting remote uploads. Compare frame bytes/decoded pixels and geometry with existing TIFF decoding using public fixtures; include a sparse/large-offset BigTIFF fixture that does not require huge physical test storage.

**Suggested implementation order**

| Priority | Deliverable | Completion criterion |
| --- | --- | --- |
| 1 | Metadata fidelity, deterministic per-slide ingest, final publication state | Synthetic end-to-end tests cover DERIVED metadata, dimensions, repeated ingest, A then A+B, failed generation, and crash/retry visibility. |
| 2 | Predictable frame-path cost and memory | Native warm lookup is independent of total frame count; metadata is lazy; duplicate loads are coalesced; decode/response/cache budgets hold under concurrent requests. |
| 3 | Local-first VPS smoke deployment | Reproducible Linux build, service shutdown/restart, gateway access, request/error metrics, backup/restore, and a small remote-viewing trial with controlled fixtures. This can proceed before S3, ZIP, or TIFF are complete. |
| 4 | Logical-member and storage-placement interface | The same shell serves owned local sources through the new reader; moving a source placement does not change DICOM identities or recipes. |
| 5 | S3 bulk-source backend | Byte/pixel parity with local reads, bounded request counts, verified ranges, retry/cancellation tests, and recovery from interrupted uploads. Keep the first deployment single-writer. |
| 6 | Owned MRXS preservation in store-only ZIP64 | Ingest survives deletion of the external test copy; tile bytes match; exported ZIP restores the complete original file tree and member hashes. |
| 7 | Native tiled TIFF/BigTIFF profile | Original bytes retained; JPEG-table handling, metadata fidelity, geometry, and local/S3 range parity tested. TIFF and ZIP64 can proceed independently once priority 4 lands. |
| 8 | Durable repair/admission jobs, migrations, wider DICOMweb | Recoverability and version compatibility are explicit before STOW or broader native profiles. Add PostgreSQL/replicas when actual deployment needs require them. |

The highest-value testing addition is a small public, synthetic archive integration corpus. Existing unit and private-fixture tests provide substantial coverage, but the two CLI publication failures and HTTP metadata defect above passed the current suite. Add process-level HTTP tests rather than relying only on route/selector tests; the current test target does not compile `archive_http.c`. Include memory-budget, concurrent cold-cache, corrupt-source, supported-version, ZIP64-offset, and S3 fault-injection cases as those features are introduced.
